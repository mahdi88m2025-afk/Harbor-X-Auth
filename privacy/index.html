Harbor X — Connected accounts privacy

Prepared 2 November 2026. Upcoming connector build. Splash.

Scope and release status

This notice describes the upcoming Harbor X connector changes, not a claim that they shipped in v0.9.26. Harbor X is an independent Windows media app by Splash, based on Harbor. Connections to Trakt, SIMKL, AniList and MyAnimeList are optional. Trakt currently uses a Development registration: only its owner and officially added members can authorize it. No unrestricted Production access is claimed.

Signing in

Each user authorizes their own account on the provider website. Harbor X never asks for provider passwords. Trakt and SIMKL use Authorization Code with PKCE S256; MyAnimeList uses its supported PKCE plain method. AniList uses its documented implicit flow and returns the token in a URL fragment. Per-attempt state, exact callback matching and a ten-minute authorization deadline protect the response. No application-wide Client Secret is embedded.

Local and hosted callbacks

The desktop app serves Trakt and SIMKL return pages on 127.0.0.1 only, on their registered fixed ports, when a connection starts. No Python helper is required in the prepared desktop mode. Requests are not logged or persisted, and this receiver never exchanges tokens. It closes after ten minutes without a new attempt or when the app process exits. AniList and MyAnimeList return through static GitHub Pages pages. GitHub receives the initial request, IP and query parameters; URL fragments are not sent by HTTP. The pages have no analytics, third-party assets or token-exchange server. Manually copied responses can remain in browser/OS clipboard history; paste them only into Harbor X, never into support or public issues.

Data read and sent

Features may read account identity, avatar, provider library/watchlist/history, media IDs, statuses, episode counts and dates. SIMKL also caches explicit episode records and paused-playback data. It retains only the returned account ID/name from its settings response. Trakt comments, ratings and watchlist actions send the values you explicitly submit. Playback events can send identified media, episode coordinates and progress; completion can mark an episode watched. Anime completion can advance AniList or MyAnimeList progress. No content stream is sent to these providers by these tracking connectors.

Your sync choices

Primary read sources choose the data shown in the unified tracking view; Local only selects local data. They are separate from Record playback destination switches, which default off. AniList/MyAnimeList also retain their provider Sync watch progress preference. Enabling a destination allows real account updates. Multiple enabled destinations receive local playback independently: provider reads are never forwarded as writes, and remote removals are not mirrored to another provider. Manual SIMKL status actions require per-item confirmation.

Storage and retention

Access and refresh tokens use Windows current-user DPAPI, scoped to the Harbor profile, provider and public registration ID; a working copy also exists in memory. This does not protect against all programs running as the same Windows user. List/episode/playback caches and delivery-ledger event IDs with success/uncertain markers are local and are not all encrypted. Disconnect removes the active local grant and attempts provider revocation where implemented. If revocation fails, the app explains that the user should revoke access in provider settings. Existing cached library snapshots are retained rather than silently erased and stay scoped to their account/profile; removing local application data can remove them. Provider-side records are managed at the provider and are not deleted just by disconnecting Harbor X.

Other services and safety

The callback pages and these connectors have no publisher-operated credential relay. This is not a complete network audit of every app feature. Metadata providers, addons, image hosts and sources selected by the user can receive their own requests under their policies. Use sources and content you are entitled to access. Never share tokens, private keys, callback responses, personal account exports or passwords in public reports.

Contact and provider policies

For privacy questions use the Harbor-X-Auth repository Issues without posting sensitive details. Manage connected applications and provider-side records in each provider account.
